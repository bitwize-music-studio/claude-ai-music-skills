## Dependency updates

Nothing in your content, audio or documents folders changes, and no config keys change. This release moves the pinned versions in `requirements.txt`. The plugin updates through the marketplace, but the venv at `~/.bitwize-music/venv` only changes when you run the fix command, so until then the MCP server keeps running on the old packages.

### What changed for me as a user?

- **pypdf 6.16.1 → 6.19.0 (security).** Eight high-severity advisories published 2026-10-01, all resource exhaustion on crafted PDFs. pypdf is used by `create_songbook` and `prepare_singles`, which read your own MuseScore exports, so the practical exposure was low. Update anyway.
- **mcp[cli] 2.0.0 → 2.3.0.** The server keeps working on any SDK from 1.28.1 up, so nothing breaks before you update. One visible difference afterwards: when a tool crashes unexpectedly, the client sees only `Error executing tool <name>`, and the traceback goes to the server log. Tools that fail normally still return their usual JSON error.
- **playwright 1.62.0 → 1.63.0.** Chromium 153 instead of 151. Until you run the manual step above, document-hunter fails at browser launch with Playwright's "Executable doesn't exist" error.

Also new in this release, and opt-in: experimental OpenAI Codex discovery of the plugin ([#548](https://github.com/bitwize-music-studio/claude-ai-music-skills/issues/548)). Nothing changes for Claude Code.
