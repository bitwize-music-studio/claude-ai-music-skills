## Dependency updates

Nothing in your content, audio or documents folders changes. This release moves the pinned versions in `requirements.txt`. The plugin updates through the marketplace, but the venv at `~/.bitwize-music/venv` only changes when you run the fix command, so until then the MCP server keeps running on the old packages.

### What changed for me as a user?

- **Pillow 12.3.0 → 13.0.0 (security).** pip-audit lists 39 advisories against 12.3.0, all fixed in 13.0.0; Pillow's release notes rate two of its fixes critical (a JPEG decoder buffer overflow, and stale image storage reused after a mode change). Pillow reads the album art for promo videos. 13.0 is a major release, but none of its breaking changes reach the plugin.
- **pypdf 6.19.0 → 6.21.4 (security).** 18 advisories against 6.19.0, all fixed by 6.21.4; most let a crafted PDF cost excessive time or memory. pypdf is used by `create_songbook` and `prepare_singles`, which read your own MuseScore exports, so the practical exposure is low. Update anyway.
- **reportlab 5.0.1 → 5.1.0.** It drops Python 3.9, which is below the plugin's 3.11 floor. Its changelog lists security fixes in 5.0.2 and 5.0.3 that have no published advisory.
- **playwright 1.63.0 → 1.64.1.** Chromium 156 instead of 153. Until you run the manual step above, document-hunter fails at browser launch with Playwright's "Executable doesn't exist" error.
- **boto3** moves to 1.43.123, a routine update.

Also new in this release, and opt-in: working through Suno's official MCP server, and having your Codex CLI make album covers. Neither changes anything until you set it up.
